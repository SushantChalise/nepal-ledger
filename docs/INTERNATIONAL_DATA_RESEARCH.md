## 2. INDICATOR MASTER LIST — Top 3 Sources

### Source 1: `imf-weo` — IMF World Economic Outlook (DataMapper API)

**Why it leads:** Only source with 5-year forward projections for GDP, debt, fiscal balance — entirely absent from WDI. Directly powers the "Borrowed Time" pillar. Simplest API in the research: `GET https://www.imf.org/external/datamapper/api/v1/{indicator}/NPL` — no auth, no pagination, clean JSON.

| Slug | IMF Code | Unit | Description | Why it matters |
|---|---|---|---|---|
| `weo-gdp-current-usd` | `NGDPD` | usd_billion | GDP, current prices (USD) | Size of economy; benchmark cross-check vs WDI |
| `weo-gdp-real-growth-pct` | `NGDP_RPCH` | percent | Real GDP growth (% change) | Core Pulse KPI; provides projections WDI cannot |
| `weo-gdp-per-capita-current-usd` | `NGDPDPC` | usd | GDP per capita (current USD) | Living standards benchmark |
| `weo-gdp-ppp-intl-dollar` | `PPPGDP` | intl_dollar_billion | GDP, PPP valuation | Cross-country comparison base |
| `weo-inflation-avg-pct` | `PCPIPCH` | percent | CPI inflation, average (% change) | Cross-check vs NRB NCPI; WEO adds projections |
| `weo-current-account-pct-gdp` | `BCA_NGDPD` | percent | Current account balance (% GDP) | Money In/Out balance; remittance surplus signal |
| `weo-govt-revenue-pct-gdp` | `GGR_NGDP` | percent | General government revenue (% GDP) | Money Wasted comparator |
| `weo-fiscal-balance-pct-gdp` | `GGXCNL_NGDP` | percent | Govt net lending/borrowing (% GDP) | Borrowed Time core series |

| `weo-unemployment-rate-pct` | `LUR` | percent | Unemployment rate (% labour force) | Cross-check ILO modelled; projection value add |
| `weo-population` | `LP` | persons | Population | Denominator for per-capita series |

**Coverage:** 1980–2031 (historical + 5-year projection). Nepal data reliable from ~1990.
**Period convention:** WEO uses calendar years internally; for Nepal, "2024" maps to approximately FY2081/82 (same WB convention — document explicitly in parser).

## 3. SEQUENCED BUILD PLAN

### Batch 1 — Quick Wins (reuse WDI pattern, JSON API, high value) — 1 session each

These all follow the established `wb_wdi` scraper pattern: TypeScript ingest CLI downloads JSON, passes local file to deterministic Python parser, parser outputs `staging_indicator_values` rows.

**B1.1 — `imf-weo`** (IMF World Economic Outlook, DataMapper REST)
- Pattern: Identical to `wb_wdi`. Download 13 indicators via DataMapper JSON. Parser maps to `weo-*` slugs.
- New work needed: source profile, 13 indicator rows, ingest CLI `scripts/ingest-imf-weo.ts`, parser `scrapers/imf_weo/parser.py`
- Period dating: calendar year → BS FY mapping documented in parser (same as WDI)
- ADR trigger: none — JSON API, no new enum, no new schema table needed if indicators land in `approved_indicator_values`
- Gate: cross-check `weo-gdp-real-growth-pct` vs `wdi-gdp-growth-annual-pct` (tolerance ±3 pp); both cover the same concept

**B1.2 — `wb-pip`** (PIP Poverty Platform, REST JSON)
- Pattern: Close to `wb_wdi`. Single endpoint per query. Parser emits 10 rows per survey year.
- New work: source profile, 10 indicator rows, ingest CLI `scripts/ingest-pip.ts`, parser `scrapers/wb_pip/parser.py`
- Important distinction: the `fill_gaps` query flag (set to true) produces interpolated rows — mark `confidence_grade='B'` for non-survey years, `'A'` for 1995/96, 2003/04, 2010/11, 2022/23 anchors. Use `observation_basis` enum if it exists, or `notes` field.
- Cross-check: `pip-gini` vs `wdi-gini-index` — expect close but not identical (different methodology)

**B1.3 — `hdr-composite`** (UNDP HDR bulk CSV, single file)
- Pattern: Download one CSV URL → Python parser slices Nepal row (`iso3 == 'NPL'`) → emits 18 series × ~34 years = ~612 staging rows
- New work: source profile, 18 indicator rows, ingest CLI `scripts/ingest-hdr.ts` (downloads CSV, passes to parser), parser `scrapers/hdr_composite/parser.py`
- Period convention: HDR year labels are calendar years; map to AD year with BS FY note in metadata
- Critical: HDI column is `hdi_2023` = 0.622; IHDI column is `ihdi_2023` = 0.548. Parser must not confuse them. Validate against known anchor: Nepal HDI 2023 = 0.622.

**B1.4 — `imf-fsi`** (IMF Financial Soundness Indicators, legacy SDMX-JSON)
- Pattern: Single legacy endpoint → JSON → parser extracts quarterly NPL ratio, capital adequacy, return on assets
- Endpoint: `GET http://dataservices.imf.org/REST/SDMX_JSON.svc/CompactData/FSI/Q.NPL`
- New work: source profile, 8 indicator rows, ingest CLI `scripts/ingest-imf-fsi.ts`, parser `scrapers/imf_fsi/parser.py`
- Period convention: quarterly — use `reporting_period_type='quarterly'`; map to NRB BFI quarterly for cross-check
- Rate limit awareness: 10 req/5 sec on `dataservices.imf.org` — single call, no issue

**B1.5 — `aiddata-gcdf`** (AidData Chinese Finance v3.0, bulk CSV on Figshare)
- Pattern: Download Figshare CSV (~150 MB), filter `recipient_iso3 == 'NPL'` in parser (~handful of rows), emit project-level records
- New work: source profile, decide if projects land in `approved_indicator_values` or a new `external_projects` table (see Schema Impact)
- Effort: small — the Figshare download is straightforward; Nepal rows are few (~5-10 projects)

**B1.6 — `fsi-fragile-states`** (FSI annual XLSX via Mendeley pre-compiled)
- Download: `https://data.mendeley.com/datasets/bhbcjtgjdm/1` — one file, 2006–2024, 12 sub-indicators
- Parser: filter Nepal row, emit 13 indicators × 19 years = 247 staging rows
- Effort: trivial — single Excel, deterministic extraction

**B1.7 — `ti-cpi`** (Transparency International CPI, annual XLSX)
- Download: Annual XLSX from `transparency.org` (pattern: last 20 years on same page)
- Parser: Nepal row → 2 indicators (score + rank) × 20 years = 40 rows
- Effort: trivial

**B1.8 — `ilostat-modelled`** (ILOSTAT bulk gzip CSV)
- Download: `GET https://ilostat.ilo.org/data/bulk/ref_area/NPL_A.csv.gz` (daily updated)
- Parser: decompress in memory, filter to 8 target indicator codes, emit rows
- Note: Bulk CSV contains ALL Nepal indicators (~500 series). Parser filters to the 8 priority slugs. Cross-check ILO unemployment vs WEO LUR (expect different methodology, tolerance ±5 pp).

### Batch 2 — Medium Effort (new API pattern or SDMX, structured data) — 1–2 sessions each

- New work: source profile, ~24 indicator slugs (4 metrics × 6 corridors), ingest CLI, parser

**B2.4 — `oecd-dac-crs`** (OECD CRS, SDMX bulk CSV)

- Schema question: does this replace / augment existing `foreign_aid_facts`? The current table is built from MoF White Book (Nepal-side reporting). CRS is donor-side. Both matter — they will diverge. Needs ADR on how to reconcile / which is authoritative for which sub-question.
- New work: source profile, ingest CLI, parser, ADR on CRS vs White Book reconciliation policy

**B2.5 — `ophi-global-mpi`** (OPHI MPI Table 8, XLSX)

- Nepal has 6 time points (2001–2022) — 3 indicators × 6 years = 18 rows
- New work: source profile, 3 indicator rows, ingest CLI, parser
- Cross-check: `ophi-mpi-incidence` (20.1%) vs `pip-poverty-headcount-365` (expect rough alignment — different methodology, different poverty dimensions)

**B2.6 — `imf-bop-bpm6`** (IMF BOP BPM6, legacy SDMX-JSON)

## 5. TOP 3 SURPRISES

**Surprise 1 — Nepal currently has a current account SURPLUS (H1 FY2026, +6.7% of GDP)**
The "chronic current account deficit" narrative that underpins parts of the Money Out pillar is outdated. WEO/BOP data will show that remittances have surged to 16.6% of GDP and reserves are at 18.1 months of import cover — a structural reversal. The WEO and IMF BOP ingests will immediately surface this contradiction with NRB DNE's older framing. Editorial consequence: the "Borrowed Time" pillar needs to reframe from "Nepal is running out of dollars" to "Nepal's solvency is entirely remittance-dependent — one Gulf recession away from reversal." The projection series (WEO 5-year forward) is what makes this actionable, which is exactly why `imf-weo` is the P1.1.

**Surprise 2 — The NSO Nepal CKAN portal (`data.nsonepal.gov.np`) has 2,600+ datasets with a public CKAN API, but it is entirely absent from the current 70-source registry**
This is Nepal's own national statistics office publishing QGDP, provincial GDP by industry, NLSS microdata, manufacturing surveys — all with a machine-readable API (`/api/3/action/package_list`). The strategic gap: Nepal Ledger currently has mostly NRB-sourced data (monetary/financial) and MoF-sourced data (fiscal), but almost nothing from CBS/NSO directly. The CKAN portal is the structural bridge to CBS's real-sector and welfare datasets. A scoping session to survey the 2,600 datasets and identify the 20 highest-value ones should precede any parser work here. Elevate from "Defer" to the top of Batch 3 planning once the feature-build priorities are clearer.

**Surprise 3 — DoFE labour approvals data (already registered as `dofe-labour-migration`, stub) is the single highest-confidence source for Nepal's primary income driver**
Remittances = 26% of GDP = ~Rs 1.75 trillion/year. Every rupee of that flows downstream from a labor approval decision tracked in FEIMS. The DoFE annual reports have 16 years of permits-by-destination-country with sex disaggregation. This source is already registered (stub) but paused — upgrading it to active is not a new registration problem, it is a parser-build problem. Given that the entire remittance pillar ("Money In") hangs on this data, and given that ILO/IOM/WB all re-publish DoFE data rather than generating their own, the DoFE annual PDF parser should be treated as equivalent priority to the API sources in Batch 1 — not deferred to Batch 3. Consider pulling `dofe-labour-migration` parser build into Batch 2 alongside the WB RPW corridor-cost source, so both sides of the remittance story (flow volume and transfer cost) are built together.

## 1. BIS (Bank for International Settlements)

**What exists:** Nepal is NOT a reporting country in BIS Locational Banking Statistics (LBS) or Consolidated Banking Statistics (CBS) — it does not report to BIS. However, Nepal appears as a **counterparty country** in the CBS. This means you can query what BIS-reporting banking systems (31 countries, covering bulk of global banking) hold as **claims on Nepal** — loans to Nepali banks and corporates from foreign banks.

**Value:** Foreign bank exposure to Nepal — how much Swiss, Japanese, US, Indian, UK banks are owed by Nepali counterparties. Directly relevant to "money captured by foreign finance."

**API/Download:** BIS Data Portal at `data.bis.org` provides bulk download and SDMX-based API. CBS data filter by counterparty country = Nepal (ISO code NP). Format: SDMX, CSV, bulk ZIP.

**URL:** `https://data.bis.org/topics/CBS/tables-and-dashboards`

**Value to mission:** Medium-high. Shows Nepal's foreign debt exposure to international banking sector, not otherwise visible in NRB data.

## 3. IMF/BIS Reporting Obligations — SDDS/GDDS/e-GDDS

**What exists:** Nepal implemented **e-GDDS in June 2017** (press release: imf.org/en/News/Articles/2017/06/13/pr17218). Nepal is NOT on SDDS (reserved for capital-market access countries). Under e-GDDS, Nepal publishes a National Summary Data Page (NSDP) hosted by Nepal Rastra Bank, using SDMX format. The NSDP links to data published by NRB, CBS/NSO, and the Financial Comptroller General Office (FCGO/MOF).

**Critical datasets unlocked via IMF e-GDDS/NSDP:**
- NRB monetary statistics (SDMX)
- NRB balance of payments (SDMX)
- MOF fiscal/government finance data (SDMX)
- CBS national accounts (SDMX)

**IMF datasets with Nepal coverage (all accessible via SDMX 2.1/3.0 API at `data.imf.org`):**
| Dataset | IMF code | Nepal coverage | Notes |
|---|---|---|---|
| International Financial Statistics | IFS | Yes | BOP components, money supply, exchange rates, interest rates |
| Government Finance Statistics | GFS / GFS_COFOG | Yes | Revenues, expenditures, debt by function |
| Balance of Payments / IIP | BOP_AGG | Yes | Full BPM6 methodology |
| Direction of Trade Statistics | DOTS | Yes | Bilateral trade partner breakdown |
| Financial Soundness Indicators | FSI | Yes — quarterly | NPLs, capital adequacy, provisioning (NRB reports) |

**IMF DOTS for Nepal is particularly high-value** — it provides bilateral trade by partner country, which NRB/Customs data doesn't cleanly expose.

**IMF FSI for Nepal:** Core + additional FSIs compiled by NRB quarterly, available in IMF FSI database. Current NPL ratio: 5.2% (April 2025). This is not in WDI and is not otherwise in your covered sources.

**API:** `data.imf.org` SDMX API (Swagger documented). All datasets free.

**Value to mission:** Very high. IMF FSI + DOTS + GFS fill structural gaps not covered by NRB CMEFs or MOF Red Book.

### SURPRISING FINDINGS AND CAVEATS

1. **DOTS was renamed IMTS in September 2025.** The legacy `DOTS` dataflow ID still works in SDMX Central but the new data portal uses `IMF.STA:IMTS`. Any existing pipeline code using "DOTS" needs to verify which endpoint it's hitting.

2. **IFS no longer exists as a single dataset.** As of 2025, the IMF restructured IFS into topic-based datasets (CPI, EXR, INR, NAG, LMI, etc.). Code that queried `IFS` directly against the new api.imf.org will get zero results. Use the `IMF_FLAG` filter on topic datasets to replicate former IFS queries.

3. **Nepal currently has a current account SURPLUS (not deficit)** as of H1 FY2026 — 6.7% of GDP. The chronic deficit narrative is outdated. Remittances surged to 16.6% of GDP, building reserves to 18.1 months of import cover. WEO projections will show whether this is sustained.

4. **Nepal's ECF program ended June 2026** (seventh review completed June 8, 2026). This means the quarterly programme monitoring data (macro conditionality, structural benchmarks) will no longer be produced. The last ECF report is the final structured fiscal data source for programme-era indicators.

5. **Article IV data is PDF-only and always will be.** No IMF API serves Article IV statistical appendix tables in machine-readable form. Nepal's Article IV is produced approximately every 12-18 months. The only automation path is PDF parsing.

6. **Invalid SDMX queries on api.imf.org return HTTP 200 with empty data rows, not 4xx errors.** A pipeline must check for empty response bodies, not just HTTP status codes.

7. **Nepal's GFS reporting to IMF has coverage gaps.** The COFOG (functional expenditure by purpose) breakdown for Nepal is typically available for only 5-7 years in the IMF GFS database, with significant interpolation. Treat GFS Nepal COFOG data as Tier B confidence.

8. **CPIS/CDIS participation by Nepal is minimal.** Nepal does not file comprehensive Coordinated Portfolio Investment Survey or Coordinated Direct Investment Survey returns (Nepal's capital account is partially restricted). External debt creditor detail is better accessed via World Bank IDS or JEDH.

9. **All IMF APIs are free, require no API key, and have no registration requirement.** The only constraint is the rate limit on the legacy dataservices.imf.org endpoint (10 req/5 sec). The new api.imf.org is more permissive.

10. **WEO projections extend to 2031 in the April 2026 edition** (5 years forward). This is the only source of IMF-authorized GDP, inflation, and fiscal projections for Nepal — entirely absent from WDI.

### SURPRISING FINDINGS AND CAVEATS

1. **IDS creditor-level data requires a completely different API call structure.** The standard `country/NPL/indicator/DT.DOD.BLAT.CD` returns "indicator not found." You must use `sources/6/country/NPL/series/DT.DOD.BLAT.CD/counterpart-area/{code}/time/all`. This is a 4-dimensional query added in the 2021 IDS release and is not documented in the main WB API help desk articles. The Japan counterpart-area code is 701; China's code needs to be retrieved from the WB counterpart-area list.

2. **Nepal's bilateral debt is 87.9% multilateral, not bilaterally China-dominated.** Unlike many South Asian neighbors, Nepal's external debt is overwhelmingly IDA/WB + ADB (multilateral). China bilateral debt is $964M total bilateral vs. $7.9B multilateral. This is significant for the "debt trap" narrative.

3. **KNOMAD bilateral remittance flow matrix discontinued 2024.** The program that produced bilateral country-pair remittance estimates was shut down. The last bilateral matrix (showing Saudi Arabia, Malaysia, Qatar, India, US as top Nepal sources) is the 2021 edition. There is no 2022/2023/2024 bilateral matrix update. Aggregate WDI remittance figures (BX.TRF.PWKR.CD.DT) remain available.

4. **Nepal PIP data is 2023, not 2010.** Initial sources suggested Nepal's most recent PIP survey was 2010. This was wrong. NLSS-IV (2022/23) has been incorporated into PIP as of October 2024. Nepal's national poverty rate is 20.3% (2023), down from 25.2% (2010). The Gini fell from 32.8 to 30.

5. **Nepal is NOT in the BOOST open budget portal** but has a dedicated Nepal Fiscal Dashboard (Tableau, FY2018–FY2024) covering all three federal tiers. This is a better alternative for sub-national fiscal data.

6. **RPW has no machine-readable API.** Despite being one of the most valuable datasets for Nepal Ledger (cost of remittance transfer directly affects the $11.3B inflow), there is no JSON/REST endpoint. Data lives in Excel downloads only. The DataBank entries (source 76/77) have stale 2020 last-update dates.

7. **PPI confirmed for Nepal: Upper Trishuli-1 (216 MW hydropower, 2019 financial close, IFC $190M + MIGA $135M).** No REST API for PPI; only STATA bulk download or custom query on portal. Nepal energy sector PPP pipeline is growing rapidly post-2015 earthquake recovery.

8. **WGI indicator codes do not work on the standard API route** (`CC.EST` returns "not found"). WGI data is accessible only through the DataBank interface or bulk download at `info.worldbank.org/governance/wgi/`. This is a known WB API limitation for the WGI source.

9. **Nepal's SPI score is declining** (65.7 in 2021 → 60.4 in 2024), suggesting statistical capacity has weakened post-COVID. This should calibrate confidence in Nepal-reported data across all WB-ingested series.

10. **DT.DOD.PVLX.CD (present value of external debt) only has 2024 data for Nepal.** The series is nearly empty before 2024 — WB only recently started computing this for Nepal, likely tied to the DSSI/DSA process. Not useful for time-series work.

## 1. ILOSTAT API — Access Methods

### 1A. SDMX REST API (Primary Programmatic API)

**Base URL (current):** `https://sdmx.ilo.org/rest`

**Dataflow query pattern:**
```
GET https://sdmx.ilo.org/rest/data/ILO,DF_{INDICATOR_CODE}/{KEY}
```
Where `{KEY}` is a dot-separated dimension filter (e.g., `NPL..SEX_T+SEX_M..`).

**Dataflow identifier format:** `ILO,DF_EMP_TEMP_SEX_AGE_NB` (agency=ILO, prefix=DF_, then the indicator code).

**Output formats:** SDMX-ML (XML), SDMX-JSON, SDMX-CSV. Use HTTP `Accept` header to specify, e.g. `Accept: application/vnd.sdmx.data+json`.

**Authentication:** None required. Fully open / no API key needed.

**Rate limits:** Not publicly documented. No published cap found across all sources. Treat as a polite-use open API.

**Swagger UI:** `https://sdmx.ilo.org/index.html` (returns 403 to scrapers but exists).

**Base URL:** `https://ilostat.ilo.org/data/bulk/`

- `https://ilostat.ilo.org/data/bulk/ref_area/NPL_A.csv.gz` — all annual indicators for Nepal

**Format:** Gzipped CSV. First row is headers. Decimal separator is `.`. Dictionary/codelist files are plain CSV.

**Update frequency:** Daily at 12:00 Paris time.

**Table of contents (indicator index):**
```

https://ilostat.ilo.org/data/bulk/ref_area/table_of_contents_en.rds
```

**~500 indicator datasets, ~700 ref_area datasets.** There is no rate limit on bulk download; it is designed for automated daily pulls.

## 11. Surprising Findings and Caveats

**Caveat 1 — Nepal wages data is a near-void.** The ILOSTAT COND database has almost nothing usable for Nepal beyond the 2017/18 NLFS. There is no enterprise survey. Wage share of GDP is modelled, not observed. If Nepal Ledger wants real wage data, the Ministry of Finance's data.mof.gov.np and CEIC are better sources for partial series.

**Caveat 2 — DoFE has no public API.** The FEIMS system is the best source of migrant worker data by destination country, but it is behind a government portal with no machine-readable export. Data is in PDFs and yearly reports. Scraping will be needed, or direct engagement with DoFE/ILO-Kathmandu for a data-sharing arrangement.

**Caveat 3 — NLFS 2017/18 is stale.** Almost all survey-anchored ILOSTAT data for Nepal is 7+ years old. The ILO modelled estimates fill the gap but carry a B-confidence tag. CBS was expected to conduct NLFS IV in 2024/25 — if completed, it will reset all the modelled baselines.

**Caveat 4 — ILOSTAT website blocks direct web fetches.** The ilostat.ilo.org domain returns HTTP 403 to automated fetchers (confirmed across all attempts in this research). Use the bulk download URLs directly (they work) or the SDMX API at `sdmx.ilo.org/rest`.

**Caveat 5 — IOM does not have independent Nepal outbound worker data.** IOM's value for Nepal Ledger is the Migration Governance Indicators (qualitative) and the GMDP portal's bilateral migrant stock data (UN DESA, decadal). For counts of workers leaving Nepal by country: use DoFE exclusively.

**Caveat 6 — Child labour data gap post-2018.** The next child labour baseline for Nepal will come from CBS's next major survey. The SIMPOC/ILO IPEC programme does not have an independent annual Nepal series.

**Surprising finding — Informal employment is 62%.** Nepal's informal economy is massive (62.2% of employment). This means the formal wage/employment statistics cover less than 40% of the labour market. The "Money In" and "Where Money Becomes Wealth" pillars should foreground this caveat on all employment visualisations.

**Surprising finding — Migration is now diversifying beyond Gulf.** FY2023/24 data shows significant flows to Central/Eastern European countries (Poland, Romania, Croatia, etc.). This is a structural shift that is not yet reflected in most databases that still show GCC-dominant patterns.

### 10. Surprising Findings / Caveats

1. **Nepal's recipient code is 660, not "230" or "NPL".** The OECD DAC uses numeric codes in CRS, not ISO alpha-3. Getting this wrong will return zero rows. Confirm from the machine-readable codelist.

2. **India is Nepal's largest bilateral creditor by outstanding stock but reports nothing to OECD DAC or IATI.** The only structured data on Indian lending is Nepal's own AMIS (partial) and MEA/EXIM press releases. AidData does not comprehensively cover Indian finance (their "GCDF" focuses only on China). This is a material gap.

3. **CRS rate limit is only 20 calls/hour.** For a full Nepal CRS dump (all years, all donors), use the bulk CSV download path (`format=csvfilewithlabels`) in a single call rather than paginating with JSON. This avoids the rate limit.

4. **OECD.Stat is deprecated.** The old `stats.oecd.org` endpoint (`stats.oecd.org/Index.aspx?DataSetCode=TABLE2a`) still works but is no longer updated. Use `sdmx.oecd.org/public/rest/...` exclusively.

5. **IATI's free tier is very restrictive.** 100 calls/week is insufficient for a full Nepal sync. Apply for Full Access (free, by approval at developer.iatistandard.org). The IATI Registry replacement happening in late 2025 may affect endpoint URLs.

6. **AidData has no API.** It is bulk-download only. For Nepal Ledger's pipeline, this means a scheduled bulk download and parse, not incremental API pulls.

7. **FTS is humanitarian-only.** Nepal's ODA is overwhelmingly development finance, not humanitarian. FTS matters most for earthquake/disaster response years (2015 Gorkha: ~$1.1B tracked). In normal years, Nepal barely appears in FTS.

8. **Nepal's WB IDS data shows external debt/GNI at 23.3% (2024)**, well within sustainable range, but debt service has grown from $228M (2014) to $537M (2024) — 135% increase. This is a key "Money Out" indicator.

9. **Nepal's LDC graduation (2026):** Nepal is scheduled to graduate from Least Developed Country status in 2026. This will affect ODA eligibility and potentially the terms of future financing. The CRS recipient code will likely remain 660 but classification may shift.

10. **The foreignassistance.gov dataset was effectively frozen in early 2025** due to US government data publishing changes. The Andrew Heiss mirror (foreignassistance.andrewheiss.com) captures the December 2024 state and is the reliable source for USAID/State historical data.

### Surprising Findings and Caveats

1. **Edible oil re-export anomaly is now Nepal's top "export."** In FY2024/25, Nepal's crude soybean oil imports surged 628% to Rs 94.8B, most of which was re-exported to India. This inflates both import and export figures massively. Comtrade will show Nepal as a major vegetable oil exporter, which is misleading. Nepal Ledger must annotate this.

2. **Hydropower exports to India (~Rs 17.5B in FY2024/25) are invisible in standard Comtrade goods data** because electricity is HS 2716 — a very small HS chapter that is often inconsistently reported. BOP data (NRB) captures it more reliably as services/electricity trade. Cross-reference NRB reports + Comtrade HS 2716.

3. **ITC TradeMap has no API** — despite appearing in many "trade data API" lists. Confirmed: web-scraping only. Use Comtrade API instead.

4. **WTO trade-weighted average tariff for Nepal (41.5% in 2023) is massively higher than simple average (12.8%)** — this divergence indicates Nepal's highest tariffs fall heavily on high-import-value products (likely petroleum, vehicles, beverages). This is an important public-finance and Money Captured story.

5. **Nepal's current account turned to surplus (~6.7% of GDP in H1 FY2025/26)** — remittances are so large (Rs 1.75T in FY2024/25, ~26% of GDP) that they cover the entire merchandise trade deficit. The current account is misleadingly healthy, masking a chronic goods-trade dependency.

6. **NRB FOREX API** (`https://www.nrb.org.np/api/forex/v1/`) is functional, free, no key required — it's the only Nepal government API that works programmatically. Useful for exchange rate normalization in trade value calculations.

7. **Nepal graduated from LDC status target is 2026** — this will remove preferential tariff access (GSP+, EU EBA, US GSP) for Nepal's exports. Comtrade + WITS TRAINS data is critical to quantify which export sectors lose preference margins.

## Surprising Findings and Caveats

1. **HDR API is effectively dead.** The advertised hdrdata.org API 2.0 (with key registration, referenced in the 2023-24 HDR API manual) returns errors. The bulk CSV is the only reliable programmatic path. Plan: scrape the annually-updated URL pattern rather than calling an API.

2. **Nepal HDI value discrepancy across sources.** The composite CSV row for Nepal shows what appears to be 0.548 (the IHDI, not HDI) as the primary value in some column positions. The confirmed HDI = 0.622 (rank 145) is in the `hdi_2023` column. When parsing, validate against the UNDP Nepal press release values.

3. **Nepal is anomalously well-documented for MPI.** Being one of three countries globally with 6 MPI time points (2001–2022) is remarkable. This means Nepal Ledger can show a 20-year poverty trajectory — far richer than the one-observation most countries have.

4. **PHDI benefits Nepal.** Nepal's PHDI (0.592) is only 5% below its HDI (0.622) because CO2 emissions per capita are ~0.5 tonnes (vs. global avg ~4.5t). The PHDI rank for Nepal is actually higher than the HDI rank. This is a significant editorial angle for the "Where Money Becomes Wealth" lens: Nepal is developing efficiently in CO2 terms.

5. **WID.world Nepal data is survey-sparse.** Unlike rich countries with continuous tax records, Nepal's WID series is interpolated between NLSS survey years (~1995, 2003, 2010, 2019). Treat as point estimates, not annual series.

6. **CEQ (fiscal incidence) likely has no Nepal data.** The coverage skews to Latin America and a few African countries. The nearest substitute is the IMF/ADB fiscal incidence work or the World Bank SOUTHASIA poverty assessments.

7. **SPI requires paid access for full CSV** but the QoG mirror at University of Gothenburg (`datafinder.qog.gu.se`) provides SPI scores in a free annual CSV with no registration.

8. **UN SDG API works with NPL as country code** (confirmed live test returning JSON for SI_POV_DAY1). However, data completeness is variable — Nepal reports only ~40% of SDG indicators to the UN system.

## 9. IsDB (Islamic Development Bank)

**Research finding:** No IsDB projects confirmed in Nepal. Nepal is not a member of the OIC (Organisation of Islamic Cooperation), and IsDB membership requires OIC membership. Search results found no Nepal-specific IsDB loans or grants.

**Conclusion:** Skip IsDB for Nepal Ledger. Not applicable.

## 11. OECD DAC Creditor Reporting System (CRS) — CRITICAL SUPPLEMENTARY SOURCE

This was not in the original 10 sources but is the most important structured source for bilateral ODA flows to Nepal.

**URL:** https://data-explorer.oecd.org — dataflow `DSD_CRS@DF_CRS` by `OECD.DCD.FSD`
**API:** OECD SDMX REST API (public, no auth)
**Format:** SDMX/JSON, CSV bulk download
**Nepal code in CRS:** `NPL` (ISO 3166-1 alpha-3)
**Coverage:** 1973–present (project-level from 2000)
**Update frequency:** Annual (Q1 release for prior year data)

**What CRS provides for Nepal:**
- All bilateral ODA loans by donor (Japan/JICA, UK, Germany, USA, South Korea EDCF, India — but NOT China, which doesn't report to DAC)
- Multilateral contributions to Nepal (ADB, WB soft windows)
- Project-level: sector (DAC 5-digit code), type of finance (ODA loan, grant, equity), flow amount, commitment vs. disbursement
- Tied/untied status, SDG markers

**Confidence:** A for DAC reporters (covers Japan, Korea, European bilaterals); China is the critical gap

**Pillars served:** Money In (all ODA flows), Money Out (concessional debt service)

## SURPRISING FINDINGS

1. **ADB KIDB already has 7 Nepal subnational codes (NEP_10–NEP_70) matching federal provinces.** This enables sub-provincial data queries if ADB collects at that level — rare capability for LDC-tier data.

2. **EIB is a significant Nepal lender (~$170M) that appears in almost no Nepal debt analysis.** The Power Expansion project controversy (indigenous rights + environmental complaints mechanism) is also a story for the "Money Wasted" pillar.

3. **AIIB's Nepal exposure is negligible in the debt stock** — it is primarily a project pipeline institution for Nepal, not yet a major creditor. The Dudhkoshi 670 MW project (2026 proposal) will change this.

4. **China EXIM has NO public API and NO machine-readable project registry.** AidData GCDF v3.0 (2000–2021) is the only structured cross-country China finance dataset. For post-2021 China loans (the BRI formalization phase began 2017, main projects post-2021), data quality degrades to B/C tier.

5. **The OECD CRS is the most overlooked high-quality source for Nepal.** It covers Japan (Nepal's largest bilateral creditor), South Korea (EDCF), UK, Germany, and all EU bilaterals. Project-level, sector-coded, annual since 2000. China's absence is a known structural gap in DAC reporting.

6. **Nepal MOF PDMO publishes monthly debt data** but primarily in PDF/Nepali. Their data shows external debt at Rs 1,530B (~$11.5B) as of mid-March 2026 — slightly above the $10.5B figure from CEIC (Q3 2024), reflecting ongoing borrowing. This is the most current and granular creditor breakdown available.

7. **ADB ADO April 2026 revised Nepal FY2026 growth to 2.7%** — down from 5.1% estimated earlier in the year, driven by 2025 civil unrest and Middle East conflict depressing remittance inflows. This is a critical data point for the "Money In" pillar given remittances are ~26% of GDP.
