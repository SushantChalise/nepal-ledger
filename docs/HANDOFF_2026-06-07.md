## Open gaps (carry forward)

### 1. Latest data not downloaded

NRB and MoF publish new files on a rolling basis. What's on disk is the Nine-Months 2082/83 snapshot. Newer CMEFs editions, recent BFI monthly files, and updated fiscal-transfer sheets have not been fetched.

**Action:** scraper / WebFetch pass against the URLs catalogued in:
- `docs/research/NRB_CATALOG_AUDIT_2026-05.md`
- `docs/research/MOF_CATALOG_AUDIT_2026-05.md`

### 2. Census Hhld18/19/20 blocked

Tables 18, 19, 20 (absent population by country and reason — the remittance-source geography dataset) have a multi-row-per-palika layout that the current `cbs_nphc/parser.py` cannot handle. The `two_mode_reader.py` extension needs to be written before these tables can be ingested.

**Impact:** Money Funnel / remittance-flow visualisations are blocked until Hhld19 lands.

### 3. DNE live ingest

The `nrb_dne` parser uses `SOURCE_ID = 'nrb-dne-xlsx'` internally, but the registered source IDs follow the `nrb-db-*` naming convention (e.g. `nrb-db-external-sector`). The FK will fail until Mother resolves the reconciliation and real XLSX files are downloaded.

See `scrapers/nrb_dne/README.md` for the reconciliation note.

### 4. Census municipality resolver (~30% unresolved)

The census fuzzy-match resolver leaves roughly 30% of palika romanizations unresolved for code-less CSVs. The fiscal-transfer ingest is unaffected (it reads the federal code column directly, bypassing fuzzy matching), but any census table delivered without a palika code column will hit this gap.

### 5. Saun-2082 BFI file (1 of 51 failed)

One BFI monthly file failed on a duplicate `source_documents` key — the 50 remaining files ingested cleanly, landing 1 836 rows in `banking_sector_facts`. Re-run the failed file after deduplicating the source-doc key.

### 6. Source-file archival deferred

The BFI, fiscal-transfer, and census CLIs self-create `source_documents` provenance rows but do NOT upload the raw bytes to Supabase Storage. The Storage upload step (present in the CMEFs/NCPI path via `ingestSource()`) is not wired for these three CLIs. This is a known gap, not a silent failure — the INGEST_RUNBOOK documents it explicitly.
